# 生态资料合规性质检技能

本 skill 用于对 Markdown 文档进行合规性质检，基于预设规则检测文档中的规范性问题。

## 重要原则（必须严格遵守，防止幻觉）

### 1. 仅使用给定规则

- **只能**使用 `references/rules.md` 中明确定义的规则
- **严禁**创造新规则、修改规则名称或规则级别
- 规则名称必须与规则文件中的完全一致（如"术语检查"、"table规范"、"隐私检查"）

### 2. 每项检查后追加写入 JSON 文件

- **每项检查完成后**：立即将结果追加写入 JSON 文件
- **质检期间**：禁止输出任何解释性文字、总结、表格
- **最终输出时**：保证输出到文件，无需输出到控制台
- 输出格式**只能**是标准 JSON

### 3. 输出前验证最终质检结果

- **只报告**真实存在问题的检查项
- 无问题的检查项**严禁报告**

### 4. 多子项规则独立报告原则

- 当质检规则包含多个子项（如"隐私检查"包含3个检查维度）时，**每个子项的问题必须独立报告**
- **禁止**将同一规则的多个问题合并为一个问题项
- 每个问题位置需要独立的 line_number 和 snippet
- 示例：如果"术语检查"在文档中有3处术语错误，应报告独立的问题项，每个指向不同的 line_number

## 输入

1. **待检查的内容**：用户输入需要检查质量的 Markdown 内容，支持以下三种形式：
   - 一段 Markdown 内容（直接输入文本）
   - 一个 Markdown 文档的绝对路径
   - 多个 Markdown 文档路径（英文逗号分隔）或一个文档目录路径

2. **`-rules` 规则筛选**：指定需要执行的规则序号（可选）
   - 格式：`-rules 1,2,3`
   - 多个规则序号用英文逗号分隔
   - 不提供则执行全部规则

3. **`--skip-tag` 跳过标签检查**（可选）
   - 格式：`--skip-tag`（无值参数，存在即生效）
   - 作用：跳过标签检查步骤（步骤2.3），仅执行规则检查
   - 示例：`D:\markdown\doc.md --skip-tag`

4. **`--skip-encoding` 跳过MD编码格式检查**（可选）
   - 格式：`--skip-encoding`（无值参数，存在即生效）
   - 作用：跳过MD编码格式检查步骤（步骤2.4），仅执行规则检查
   - 示例：`D:\markdown\doc.md --skip-encoding`

### 示例

```
# 全部检查
/markdown-compliance-quality-checker "文档路径"

# 仅检查规则1和3
/markdown-compliance-quality-checker "文档路径" -rules 1,3

# 跳过标签检查
/markdown-compliance-quality-checker "文档路径" -skip-tag
```

## 输出

输出一个质检结果JSON文件

- 默认输出目录：当前项目根目录下创建 `/output/` （如果目录不存在则先创建目录）
- 文件命名规则：`compliance-markdown-check-result.json`

### 质检结果统一 JSON 格式

```json
[
  {
    "rule_group": "xxx",
    "rule_item": "xxx",
    "rule_type": "xxx",
    "rule_name": "xxx",
    "snippet": "xxx",
    "description": "xxx",
    "rule_level": "xxx",
    "file_name": "xxx",
    "line_number": "xxx",
    "location": "xxx",
    "suggestion": "xxx"
  }
]
```

#### 输出字段说明

| 字段名 | 类型 | 描述 | 要求 |
| --- | --- | --- | --- |
| rule_group | string | 问题大类 | 固定为"通用规则" |
| rule_item | string | 规则项名称 | 必须与规则文件中的规则项名称一致 |
| rule_type | string | 规则类型 | 必须与规则文件中的规则类型一致 |
| rule_name | string | 规则名称 | 必须与规则文件中的规则名称一致 |
| snippet | string | 问题内容片段 | 直接引用文档内容 |
| description | string | 问题的具体描述 | 清晰说明问题，不包含行号 |
| rule_level | string | 级别 | 必须与规则文件中的级别一致 |
| file_name | string | 文档名称 | 必须是用户输入的Markdown文档名称 |
| line_number | string | 问题行号 | 必须从带行号的文档内容中直接获取 |
| location | string | 问题所在的行链接 | vscode://file/绝对路径:行号 |
| suggestion | string | 问题的具体修改建议 | 直接给出正确形式，不包含行号 |

## 执行流程

### 核心原则：按需读取，逐任务执行

**严禁提前批量读取所有文件。** 每个任务在执行时才读取该任务所需的文件，执行完毕后立即写入结果，再进入下一个任务。

在执行任何步骤前，在对话中先输出当前检查点：[CHECKPOINT: 开始]

**规则**：如果前一个CHECKPOINT未输出，禁止执行后一步骤。

### 第 1 步：数据准备

一次性完成所有输入解析、规则筛选和文档列表生成，避免中间文件读写循环。

#### 1.1 解析参数与读取配置

- 获取用户输入中的 `-rules` 参数列表（如果存在）
- 获取用户输入中的 `--skip-tag` 参数（如果存在），表示跳过标签检查
- 检测用户输入内容是否为文件路径：
    - 如果是 `.md` 文件或者目录路径，则为文件路径模式
    - 如果不是，作为 Markdown 内容模式处理
- **文件路径模式**：直接使用文件路径作为处理文档路径
- **Markdown 内容模式**：
    - 创建 `output/compliance/temp/auto_temp.md` 文件
    - 将用户输入的Markdown内容写入该文件
    - 将该文件的绝对路径作为后续处理的文档路径
- **仓名获取方式**：仓名即当前项目根目录的文件夹名称。从项目根目录的绝对路径中提取最后一级目录名作为仓名。例如项目根目录为 `D:\workspace\branch\cloud`，则仓名为 `cloud`。将仓名保留在上下文中供步骤2.3使用

**检测是否是Markdown内容的标准**：

- 没有明显文档路径特征（如 `D:/...、/...、./...等`）
- 不包含文件扩展名或路径分隔符
- 极长的内容（超过单行命令行输入长度）

#### 1.2 读取规则并筛选

- **此时读取**规则文件 `references/rules.md`，以及规则中引用的参考文件（如 `terms-and-abbreviations.md`、`sensitive-words-internal.md` 等，**仅在规则需要时读取**）
- 如果用户提供了 `-rules` 参数，按规则编号筛选对应规则；否则保留全部规则
- 将筛选后的规则保留在上下文中直接传递给后续步骤

#### 1.3 生成文档列表

- 读取当前技能目录下 `assets/exclude-files.json` 中的排除文件列表
- 根据文档路径生成待检查文件列表：
    - 单文件：直接加入列表
    - 目录：递归遍历该目录下所有 `.md` 文件，排除白名单中的文件名
- 将文档列表保留在上下文中

#### 1.4 批量读取待检查文档

- 一次性读取所有待检查文档的完整内容，**必须使用带行号的方式读取**，确保每行内容与行号一一对应
- 将带行号的文档内容保留在上下文中，后续步骤直接使用，**不再重复读取**

#### 1.5 清理历史结果文件

- 检查 `output/compliance-markdown-check-result.json` 文件是否存在
    - 如果存在，删除该文件，避免历史检查结果影响本次检查
    - 如果不存在，跳过此步骤

完成后必须在对话中输出 [CHECKPOINT: 数据准备完成]

### 第 2 步：执行分析

#### 2.1 基础准备

- 确保 `output` 目录存在

完成后必须在对话中输出 [CHECKPOINT: 基础准备完成]

#### 2.2 批量检查文档

对于每个待检查文档，使用步骤1中已读取的文档内容（禁止重复读取文件），逐个应用步骤1中已筛选的规则：

1. 获取当前规则分组下的所有规则文件列表
2. 对于每个规则：
    - **读取规则描述**：直接从上下文中的规则数据获取
    - **读取参考资料**：直接从上下文中的参考资料获取（如果该规则引用了参考文件）
    - **执行检查逻辑**：根据规则描述严格按照 **逐字逐行** 检查文档内容，不允许根据常识或经验进行扩展性检查
    - **检查结果格式**：检查出来的问题按照 **质检结果统一 JSON 格式** 的要求输出
    - **检查结果验证**：检查每个问题的描述和建议是否与发现问题的规则相互匹配
        - 如果不匹配，则剔除该问题结果
    - **保留结果到上下文**：将检查结果保留在上下文中，供步骤3直接汇总使用
        - 如果是非问题或者未发现问题，禁止将结果保留到上下文中

完成后必须在对话中输出 [CHECKPOINT: 批量检查文档完成]

#### 2.3 执行标签检查脚本

- 如果步骤1中解析到 `--skip-tag` 参数，则跳过本步骤，直接输出 [CHECKPOINT: 标签检查完成]
- 如果未解析到 `--skip-tag` 参数，则对每个待检查文档**逐个**执行标签检查，**每个文档检查完成后必须立即读取结果并保存到上下文，再处理下一个文档**（因为脚本每次执行会覆盖 `tag_check_result.json`，不立即读取会导致前一个文档的结果丢失）：
    - 调用当前技能目录下 `scripts/tag_checker.js` 脚本
    - 命令格式：`node <技能目录绝对路径>/scripts/tag_checker.js <md文件绝对路径> <项目根目录绝对路径>/output <仓名>`
    - `npus.json` 配置文件的路径脚本内部已通过 `__dirname` 自动定位，无需额外传参
    - 仓名从步骤1上下文中获取
    - 脚本执行后会在 `output/` 目录下生成 `tag_check_result.json` 文件
    - **立即读取** `output/tag_check_result.json` 的内容，将标签检查结果保留到上下文中，供步骤3直接汇总使用
    - 如果 `tag_check_result.json` 为空数组或不存在，则无标签检查问题，不保留结果到上下文
    - 保存完成后，再对下一个待检查文档执行标签检查

**脚本结果校验**：读取脚本输出结果时，需校验JSON格式是否正确。如果JSON解析失败或格式异常，跳过该脚本结果，不中断整体检查流程。

完成后必须在对话中输出 [CHECKPOINT: 标签检查完成]

#### 2.4 执行MD编码格式检查脚本

- 如果步骤1中解析到 `--skip-encoding` 参数，则跳过本步骤，直接输出 [CHECKPOINT: MD编码格式检查完成]
- 如果未解析到 `--skip-encoding` 参数，则对每个待检查文档**逐个**执行MD编码格式检查，**每个文档检查完成后必须立即读取结果并保存到上下文，再处理下一个文档**（因为脚本每次执行会覆盖 `encoding_format_check_result.json`，不立即读取会导致前一个文档的结果丢失）：
    - 调用当前技能目录下 `scripts/encoding_format_checker.js` 脚本
    - 命令格式：`node <技能目录绝对路径>/scripts/encoding_format_checker.js <md文件绝对路径> <项目根目录绝对路径>/output`
    - 脚本执行后会在 `output/` 目录下生成 `encoding_format_check_result.json` 文件
    - **立即读取** `output/encoding_format_check_result.json` 的内容，将MD编码格式检查结果保留到上下文中，供步骤3直接汇总使用
    - 如果 `encoding_format_check_result.json` 为空数组或不存在，则无MD编码格式检查问题，不保留结果到上下文
    - 保存完成后，再对下一个待检查文档执行标签检查

**脚本结果校验**：读取脚本输出结果时，需校验JSON格式是否正确。如果JSON解析失败或格式异常，跳过该脚本结果，不中断整体检查流程。

完成后必须在对话中输出 [CHECKPOINT: MD编码格式检查完成]

#### 2.5 执行敏感词检查脚本

- 对每个待检查文档**逐个**执行敏感词检查，**每个文档检查完成后必须立即读取结果并保存到上下文，再处理下一个文档**（因为脚本每次执行会覆盖 `prohibited_words_check_result.json`，不立即读取会导致前一个文档的结果丢失）：
    - 调用当前技能目录下 `scripts/prohibited_words_checker.js` 脚本
    - 命令格式：`node <技能目录绝对路径>/scripts/prohibited_words_checker.js <md文件绝对路径> <项目根目录绝对路径>/output`
    - 脚本执行后会在 `output/` 目录下生成 `prohibited_words_check_result.json` 文件
    - **立即读取** `output/prohibited_words_check_result.json` 的内容，将敏感词检查结果保留到上下文中，供步骤3直接汇总使用

完成后必须在对话中输出 [CHECKPOINT: MD编码格式检查完成]

### 第 3 步：汇总输出

- 直接从上下文中汇总所有检查结果到 `output/compliance-markdown-check-result.json` 文件
- **禁止读回中间结果文件再写入**，直接从上下文中的分析结果汇总输出

完成后必须在对话中输出 [CHECKPOINT: 汇总输出完成]

### 第 4 步：清理临时文件

- 删除 `output` 目录下的 `compliance` 文件夹
- 删除 `output/tag_check_result.json` 文件

完成后必须在对话中输出 [CHECKPOINT: 清理临时文件完成]

## 逐行扫描执行规范（强制遵守）

### 1. 逐行扫描顺序

- 对每个文档按行号从小到大逐行检查
- 每行从左到右逐字符/逐词扫描
- 发现问题时记录后必须继续向右扫描当前行剩余内容，不得中断当前行的扫描
- 只有当当前行从左到右完整扫描完毕后，才能进入下一行

### 2. 同行穷举规则

- 当在某行发现规则违规时，必须继续检查该行剩余内容是否还存在同类或其他违规
- 禁止因已发现一个问题而跳过同行后续内容
- 每行必须从头到尾完整扫描后才能进入下一行
- 同一行同一规则可以命中多个问题，每个问题必须单独记录

### 3. 结论验证规则

- 对每条检查结论（合规/不合规），必须在原文中定位到具体字符后再判定，**行号必须从步骤1带行号的文档内容中直接获取，禁止凭记忆心算或估算行号**
- 禁止凭对原文的印象或记忆下结论
- 特别是标注"合规"时，必须在上下文中明确记录判定依据（如：原文此处为XXX，符合规则YYY的ZZZ要求）
- 如果无法在原文中精确定位对应内容，必须回溯原文重新确认，禁止跳过
- **记录问题行号时，必须从步骤1已读取的带行号文档内容中直接获取行号，禁止通过心算或人工计数推算行号。如果上下文中带行号的文档内容已被截断，必须重新使用带行号方式读取原文档对应区域来确认行号**

## 常见幻觉陷阱（避免！）

| 陷阱 | 错误做法 | 正确做法 |
| --- | --- | --- |
| 创造规则 | 添加规则文件中不存在的检查项 | 仅使用规则文件中明确定义的规则 |
| 规则名称错误 | 使用"术语规范"代替"术语检查" | 使用规则文件中的"术语检查" |
| 扩展检查范围 | 根据常识添加规则未描述的检查项 | 严格按照规则描述的检查对象和范围执行 |
| 合并多子项问题 | 将同一规则的多处问题合并为一个问题项 | 每个问题位置独立报告，使用独立的行号 |
| 遗漏其他位置的错误 | 只报告第一处错误，忽略同一规则的后续错误 | 全面检查文档，同一规则的所有问题都要独立报告 |
| 输出多余内容 | 输出总结、表格、解释 | TL;DR, 仅输出 JSON |
| 心算行号 | 凭记忆或计数推算问题行号 | 从带行号的文档内容中直接获取行号 |

## 禁止行为

- 禁止超出规则描述范围进行检查，即便发现明显错误，遇到规则描述不明确的情况，必须跳过而非自行解读
- 禁止基于常识或经验进行扩展性检查，避免主观推断
- 禁止超出规则定义的检查范围进行检查
- 禁止不按照技能步骤执行
- 禁止不按技能步骤顺序执行
- 禁止跳过任何步骤
- 禁止合并或简化规则分类
- 禁止复制待检查文档到临时文件夹
- 禁止修改或增减规则内容
- 禁止修改文件内容，检查过程中只需要读取文件内容
- 禁止按照问题行号合并检查出的问题
- 禁止生成 CHECKPOINT 文档
- 禁止在步骤之间重复读取已在步骤1中读取过的文件
- 禁止发现一个问题后跳过同行剩余内容的检查
- 禁止凭印象或记忆对检查结论下判定，必须对照原文精确定位
- 禁止通过心算、人工计数或估算方式确定问题行号，必须从带行号的文档内容中直接获取行号

## 约束与边界

- **场景约束**：一段内容场景不校验MD专属格式（标题层级、代码块等），仅聚焦基础规范和核心正确性

## 注意事项

1. 所有使用的文件路径都应是相对路径，在执行时转换为绝对路径
2. output 目录是在当前项目根目录下
3. 步骤2的分析必须逐个检查用户输入的所有文档
4. 检查完成后需要清理临时文件，仅保留最终结果文件
5. 支持 `.md` 文件扩展名的质量检查
6. 步骤1一次性完成所有数据读取和准备，后续步骤禁止重复读取已在步骤1中读取过的文件
7. 禁止通过中间文件在步骤间传递数据，所有数据在上下文中流转
8. **仅使用给定规则文件的范围进行检查，严禁增删改规则条目**
