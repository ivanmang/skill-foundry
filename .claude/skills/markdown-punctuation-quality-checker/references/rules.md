# Markdown 标点质检规则 - 规范性检查详细说明

**重要提示：**

- 仅使用本文件中明确定义的规则进行检查
- 规则名称、规则级别必须与本文件完全一致

## 1. 规范性

检查 Markdown 文档中标点符号和空格使用是否符合统一规范。此类检查仅基于文档内容，不需要读取代码。

| 规则项名称 | 规则名称 | 规则类型 | 描述 | 级别 |
| --- | --- | --- | --- | --- |
| StaticCheck_punctuation | 多余空格检查 | 规范性 | 检查文本中是否存在多余空格，覆盖中英文排版、代码块、命令行、特殊内容、单位和数字等5个维度 | 提示 |
| StaticCheck_punctuation | 缺少必要空格检查 | 规范性 | 检查文档中是否缺少必要空格，覆盖英文单词间距、句子间距、技术术语、标点间距等18个维度 | 提示 |
| StaticCheck_punctuation | 英文内容中文符号检查 | 规范性 | 检查英文内容中是否使用了中文符号（下划线、短横线、标点符号） | 一般 |
| StaticCheck_punctuation | 连续标点符号检查 | 规范性 | 禁止出现连续两个及以上标点符号 | 严重 |
| StaticCheck_punctuation | 成对标点符号完整性检查 | 规范性 | 检查成对标点符号是否完整配对 | 一般 |
| StaticCheck_punctuation | 中英文标点混用检查 | 规范性 | 检查段落里中英文标点符号是否混用 | 一般 |
| StaticCheck_punctuation | 路径符号使用错误检查 | 规范性 | 检查路径符号是否使用错误，覆盖分隔符、混用、重复、非法字符、大小写等5项规则 | 提示 |
| StaticCheck_punctuation | 正文缺失标点符号检查 | 规范性 | 检查正文中是否缺失标点符号 | 提示 |

### 多余空格检查

- 位置：全文中的文本内容、代码块、命令行、表格、HTML表格等。
- 规则：**必须逐一检查以下5个维度，每个维度错误均需独立报告：**

  **检查维度1 - 中英文排版空格**

  1. 中文词语/句子间：分隔空格最多1个
     - 正例：我是 一个 测试【反例：我是  一个  测试】
  2. 中文标点前：不允许有空格
     - 中标符号：，。：？！
     - 正例：这是测试。【反例：这是测试 。】
  3. 中文标点后：不允许有空格
     - 中标符号：，。：？！
     - 正例：这是测试。【反例：这是测试。 】
  3. 英文单词间：仅1个空格
     - 正例：Hello world【反例：Hello  world】
  4. 英文标点后：仅1个空格
     - 标点符号：,.:;
     - 正例：This is a test.【反例：This is a test.  】
  5. 括号内侧：无空格
     - 正例：(content)【反例：( content )】
     - 正例：[item1, item2]【反例：[ item1, item2 ]】
     - 正例：{key:value}【反例：{ key:value }】
     - 正例：['case001', 0, 65536]【反例：[' case001', 0, 65536]】
  6. 中英文混用：不加空格
     - 中-英文间：不加空格
     - 中文-数字间：不加空格
     - 中文-中文间：不加空格
     - 正例：Python版本3.5、和HCCL类型、使用GPU加速
     - 反例：Python 版本 3.5、和 HCCL 类型、使用 GPU 加速
     - 【例外】产品名称白名单中的名称，中英文间加空格或不加空格均可，不视为违规
     - 白名单配置文件：references/product_names_whitelist.json
     - 正例：Atlas A3 训练系列产品、Atlas A3推理系列产品

  **检查维度2 - 代码块和命令空格**

  1. 代码中非缩进位置禁止出现连续2个及以上空格
  2. 函数名与左括号间：无空格
     - 正例：print(a)【反例：print (a)】
     - 正例：aclInit()【反例：aclInit ()】
  3. 参数间空格：仅1个空格
     - 正例：func(1, 2)【反例：func(1,  2)】
  4. 参数名与等号间：仅1个空格
     - 正例：func(epoch = 10)【反例：func(epoch=10)】
  5. 代码缩进：按语言约定
     - Python：4个空格
     - Java：4个空格或1个Tab
     - 同一代码块缩进必须一致
     - 正例
      ```
      import torch
      import torch
      ```
     - 【反例】
      ```
      import torch
         import torch
      ```
  6. 行尾：禁止多余空格
     - 正例：行尾没有空格。【反例：行尾有空格。    】
  7. 代码段中函数定义括号里的参数间“=”前后无空格
     - 正例：npu_add(input, approximate='none')【反例：npu_add(input, approximate = 'none')】

  **检查维度3 - 命令行空格**

  1. 命令与参数间：1个空格
     - 正例：ls -l /home【反例：ls  -l/home】
  2. 管道符(|)：前后各1个空格
     - 正例：cat log.txt \| grep "error"【反例：cat log.txt\|grep "error"】

  **检查维度4 - 特殊内容空格**

  1. 表格单元格内容/结构化内容：文字前后无多余空格
  2. 数值/参数：需紧凑呈现
     - 正例：2.0版本【反例：2 . 0 版本】
  3. 变量名/文件名：中间禁止空格
     - 正例：model_config.json【反例：model config.json】
     - 正例：device_id【反例：device id】
  4. 路径与URL：整体无空格
  5. 英文单词、函数变量、函数名称、接口原型、目录和路径、参数、命令：中间禁止多余空格

  **检查维度5 - 单位和数字空格**

  1. 数字与单位符号：禁止多余空格
     - 正例：3.5GHz【反例：3.5 GHz】
     - 正例：10ms【反例：10 ms】
     - 正例：100MB/S【反例：100 MB/S】
     - 正例：100GB【反例：100 GB】
  2. 数字与SI标准单位(kg、m、s等)：禁止多余空格
     - 正例：1kg【反例：1 kg】

### 缺少必要空格检查

- 位置：全文中的文本内容、技术术语、公式符号等。
- 规则：**必须逐一检查以下18个维度，每个维度错误均需独立报告：**

  1. 英文单词之间必须有至少1个空格
     - 缺少空格会被视为拼写错误
     - 正例：hello world
     - 反例：helloworld（缺少空格）

  2. 前一句尾标点与下一句首字母之间必须有1个空格
     - 适用标点：。？！等句子结束标点
     - 正例：Wrong number! Please try again.
     - 反例：Wrong number!Please try again.

  3. 技术缩写词与紧接的数字或字母之间需要适当空格
     - 适用场景：带编号时的技术术语
     - 适用术语：MSC、MS、slot、NPU、GPU、CPU、RAM、ROM、SSD、HDD等所有英文技术缩写词
     - 正例：MSC 1、MS 1、slot 3、CPU 16核、GPU 2卡等
     - 反例：MSC1、MS1、slot3、CPU16核、GPU2卡等
     - 【优先级说明】本维度优先于维度18（中英文混合不加空格），当英文缩写词紧接数字时，缩写词与数字之间需加空格

  4. 键盘组合快捷键中"+"号前后不留空格
     - 正例：Ctrl+S、Alt+Tab
     - 反例：Ctrl + S、Alt + Tab

  5. 英文标点与紧接的前一个英文单词之间没有空格
     - 适用标点：. , : ; ? !
     - 正例：word.yes
     - 反例：word .yes

  6. 货币符号/代码与金额之间没有空格
     - 正例：$3、CNY100
     - 反例：$ 3、CNY 100

  7. 破折号间距规则：
     - 短破折号前后不留空格（作减号时除外）
     - 长破折号前后加空格
     - 正例：Value range:0-65536、This is a sentence — with em dash
     - 反例：Value range: 0-65536

  8. 温度数值与温度符号之间没有空格
     - 正例：36℃、100℃
     - 反例：36 ℃、100 ℃

  9. 斜杠"/"前后不加空格
     - 正例：input/output、and/or
     - 反例：input /output、input/ output

  10. ±符号前后不加空格
      - 正例：-48±20%
      - 反例：-48 ± 20%

  11. 大于/小于号(＞、＜、≥、≤)前后必须加空格
      - 正例：X ＞ Y ＞ Z、value ＜ 100
      - 反例：X＞Y＞Z、value＜100

  12. 圆括号间距规则：
      - 前括号与前面单词：有1个空格
      - 后括号与后面单词：有1个空格
      - 括号内字符与括号：无空格
      - 正例：The user number (that is, MSISDN) is a numeric string.
      - 反例：The user number(that is, MSISDN)is a numeric string.

  13. 复合词中连字符前后不加空格
      - 例外：类似hot-and cold-rolled这样的特殊结构用法除外
      - 正例：well-known、state-of-the-art
      - 反例：well- known、state-of-the- art

  14. 表头单词和省略号之间不加空格
      - 正例：Table... Content
      - 反例：Table ... Content

  15. 公式符号（=、~、<、>等）前后必须有空格
      - 正例：x = 10、a ~ b
      - 反例：x=10、a~b

  16. 数值与单位符号中间不加空格
      - 正例：44.45mm、100MB、2.5GHz
      - 反例：44.45 mm、100 MB、2.5 GHz

  17. 软件包和版本号同时出现时的格式：
      - 标准格式：软件包名 + 1个空格 + 版本号
      - 例外：表示软件包名称和文件路径时
      - 正例：Nginx 1.14.2（标准格式）
      - 正例：nginx-1.14.2.tar.gz（文件名格式）
      - 反例：Nginx1.14.2（缺少空格）

  18. 中英文混合场景遵循中文习惯，一般不加空格
      - 【例外】产品名称白名单中的名称，中英文间加空格或不加空格均可，不视为违规
      - 正例：这是English单词、Python脚本是important、Atlas A3 训练系列产品、Atlas A3推理系列产品
      - 反例：这是 English 单词、Python 脚本是 important

### 英文内容中文符号检查

- 位置：全文中的回显、代码示例、命令、参数等英文内容。
- 规则：
  1. 回显/代码示例/命令/参数的英文单词拼写中必须使用英文下划线（"_"）
  2. 回显/代码示例/命令/参数的英文单词拼写中必须使用英文短横线（"-"），而不是中文中横线（"——"）

### 连续标点符号检查

- 位置：全文中的文本内容。
- 规则：禁止出现连续两个及以上标点符号。
- 例外场景：成对标点符号后紧接句号、问号、感叹号等结尾标点符号时不算违规。
  - 正例："这里需要用引号。"（引号后加句号）

### 成对标点符号完整性检查

- 位置：全文中的文本内容。
- 规则：检查成对标点符号是否完整配对。
- 例外场景：
  1. 字符串中的使用半边小括号作为编号格式
  2. 回显里面的标点符号不成对
  3. 数学表达式中表示区间的取值范围允许混用小括号和中括号时，括号必须成对
     - 正例：[0, 3)、[3, 6)、[6, 10)
     - 反例：0, 3), [3, 6

### 中英文标点混用检查

- 位置：全文中的段落文本。
- 规则：检查段落里中英文标点符号是否混用。
- 例外场景：代码样例、注释等英文段落不检查
- 正例1：中文段落用中文标点，英文段落用英文标点。
- 正例2：please submit them via Issues.
- 【反例1：中文语境中使用英文冒号:输出（中文段落用英文标点）】
- 【反例2：please submit them via Issues。（英文段落用中文标点）】

### 路径符号使用错误检查

- 位置：全文中的路径内容。
- 规则：**必须逐一检查以下5项，每项错误均需独立报告：**
  1. 分隔符错误。Windows中的反斜杠\\在代码中要转义成"\\\\"。
     - 反例：C:\\Users\\name\\file.txt
     - Linux中要使用正斜杠"/"，例如：/home/name/file.txt
  2. 禁止分隔符混用，既有"\\"又有"/"
  3. 禁止分隔符重复，例如"//"或者"\\\\"
  4. 禁止路径中存在非法字符，非法字符有：< > : " \| ? * + 以及空格
      - 正例：examples/add_example/report【反例：examples/add_example_*/report】等
  5. Unix/Linux路径建议统一使用小写，Windows路径保持原始大小写，Windows路径中的盘符建议使用大写，如'C:\\Users\\test'

### 正文缺失标点符号检查

- 位置：全文中的正文段落。
- 规则：
  1. 描述性句子末尾必须使用句号、问号或感叹号
      - 正例1：句末存在句号。【反例：原始大小写等,】
  2. 列表项、标题等非完整句子可以不使用句号
