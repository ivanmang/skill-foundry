# data-boundary：数据边界与提问路由

回答"这份快照能回答什么 / 不能回答什么"的唯一依据。按 scope 列出；跨 scope 需求给出去向。

## 1. 能力矩阵

| 问题 | compute | memory | summary | 去哪补 |
|------|:--:|:--:|:--:|--------|
| 哪条 pipe 是瓶颈？ | ✅ | ❌ | ✅(总览) | — |
| 计算利用率多少？ | ✅ | ❌ | ✅(卡片) | — |
| 资源冲突？ | ✅ | ❌ | ❌ | 切 compute tab |
| 逐 block 均衡 / tail？ | ✅ | ✅(若有 rows) | ❌ | 切 compute tab |
| 带宽跑满没有？ | ❌ | ✅ | ✅(卡片) | 切 memory tab |
| L2 命中率？ | ❌ | ✅ | ❌ | 切 memory tab |
| 冗余搬运量？ | ❌ | ✅ | ❌ | memory + shape 信息 |
| 理论上限几倍？ | ❌ | ❌ | ✅(roofline) | 切 summary tab |
| 芯片/核数/容量？ | ❌ | 部分 | ✅ | hardwareDetails |
| 是稳态性能吗？ | ❌ | ❌ | ❌ | **任何 scope 都不行** → msprof repeat 采集 |
| 该往哪个方向优化？ | ✅ | ✅ | ✅(粗) | optimization-advice.md（方向 + 代价 + 排除条件 + 验证方式） |
| 具体代码怎么写？ | ❌ | ❌ | ❌ | 本技能只出方向与判据，不出 API 签名 / Kernel 骨架 / TilingData 字段 |
| 改完能快多少？ | ❌ | ❌ | ❌ | 只能给该优化的**典型收益区间**，本算子实际增益须改造后重采实测 |
| 和基线/上次比？ | ❌ | ❌ | ❌ | 快照无历史 → 用户另发基线报告，两次分别解析后对比 |
| 精度对不对？ | ❌ | ❌ | ❌ | 超出 profiling 范畴 |

## 2. 回答"不能回答"的统一话术

> "该项数据在报告 <report_id> 中不存在（缺 <具体字段/表>）。可通过：① 检查采集配置是否包含该指标后重新采集；② 使用 msprof 重复采集获取。"

变体：
- 缺 repeat → "本报告为单次采集（single-shot），不能作为稳态结论。需要 warmup=10 / repeat=5 / median 的重复采集。"
- 缺历史 → "报告不含基线数据。请提供基线报告，我可按 report_id 区分两份报告做逐指标对比。"
- 解包失败 → "报告 <report_path> 解包失败（<原因>），无法读取明细。请确认文件完整或重新采集。"
- scope 缺失 → "payload 未指定 scope，默认全量解读；如需聚焦某一方面可说明。"

## 3. 数据的根本限制（对用户解释时用）

明细来自解包 `.npu-rep`（静态文件，重读内容不变）：
1. 只含采集时开启的指标 → 未勾选的指标（如 L2Cache、trace）整文件缺失
2. 单次采集 → 无稳定性信息
3. 无源码、无 shape 上下文（除非用户附）→ 理论最优值算不出
4. scope 缺失时默认全量解读；带 scope 时只解读对应部分（除非用户追问其他）

## 4. 常见追问的标准动作

| 用户追问 | 动作 |
|---------|------|
| "为什么 block 63 比别人快一倍？" | compute scope 内回答：tail block（元素数不整除），检查该 block 的元素配额 = 总量/64 向上取整 |
| "vector 98% 是好事还是坏事？" | 好事（单元没闲）+ 坏事（优化空间在指令效率而非并行度）双面回答，引出 vf 位宽利用率不可见 → 边界话术 |
| "带宽 32 GB/s 高吗？" | 必须换算全程平均并除以硬件峰值（hardwareDetails / npu-arch），否则不给"高/低"结论 |
| "这个数据和上次比呢？" | 边界话术（无历史）+ 建议发送上次快照 |
| "帮我改代码" | 给方向与判据（optimization-advice.md 对应条目），说明本技能不出代码实现；需要 Kernel 骨架 / TilingData 字段时指出这超出范畴 |
| "该怎么优化？" | 按 optimization-advice.md 出建议条目（五槽位齐全），触发条件不成立的不出；同时给"已排除的方向" |
| "这些建议哪条先做？" | 按 optimization-advice.md §5 叠加顺序表回答，并说明互斥项（如 StreamK ⊥ Full-Load）与共享预算项（UB / L1） |
| "预计能提升多少？" | 只给典型收益区间并标"典型收益/实测参考"；本算子实际增益按该条"如何验证见效"重采实测 |
