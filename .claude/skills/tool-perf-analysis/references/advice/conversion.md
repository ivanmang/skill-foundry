# conversion 族条目正文（§4.1–§4.3，Transpose / Concat / Split 等）

> 由 [optimization-advice.md](../optimization-advice.md) 索引命中后读取。前置：算子为数据转换类。**本族的性能优化本质是"按入参选对策略"，而非对单一实现调参**——选错直接慢，选对即快。因此本族建议的形态是选型判据，不是参数调整。

## 4.1 策略选型（决定性能的核心）

- **证据**：算子属 conversion 族即可；报告侧的典型症状是带宽利用率极低（逐元素路径）或 `mte3` 段大量小 strided 搬运
- **方向**：按 dtype（元素字节宽）、输入 shape、perm（转置轴序）三项入参对照命中条件选策略：

| 策略 | 命中条件 | 关键手段 |
|------|---------|---------|
| TENSOR_MOVE | 规约后 `dim == 1`，退化为纯拷贝 | 直接搬运，无需重排 |
| SMALL_SHAPE | 总字节数 < 阈值（小 shape） | SIMT 逐元素 + 魔数除法反算索引，省搬运流水固定开销 |
| CUT_ONCE | 单轴切分即可满足输入/输出 UB 约束 | 带 stride 的多维 DMA 描述符在搬运中完成 perm 取址 |
| CUT_TWICE | 需在输入、输出两方向各切一轴 | 同上，两方向切分 |
| N_LAST_TRANSPOSE | 末轴不参与转置且末轴元素数 ≥ 32 | 多维 DMA + 末轴连续搬运 |
| BIG_DIM | 规约后维度 > 多维 DMA 上限（5） | 维度拆分后多轮搬运 |
| GATHER_TRANSPOSE | 末轴参与转置（需 DAV_3510 + 编译开关） | UB 内按预生成 index 重排 |
| VCONV_TRANSPOSE (5HD) | 2D 末轴交换、16 bit、R > 5 | 片上 16×16 块转置 |
| VCONV_021 | `perm = [0,2,1]` 保 batch 转置，支持 8/16/32 bit | 片上块转置 |

- **代价与前置检查**：选型需要 dtype / shape / perm，**报告全部不可见** → 必须由用户提供，否则本条只能指出"需按入参重新选型"而不能给出具体策略
- **排除条件**：GATHER 策略受编译开关保护（默认关闭）且仅特定架构可用，关闭时相应 shape 由多维 DMA 家族覆盖；VCONV 5HD 仅支持 16 bit，021 支持 8/16/32 bit
- **如何验证见效**：换策略后带宽利用率与总耗时同时改善；策略选对时收益体现为"避免劣化"，可不强求固定百分比

## 4.2 SMALL_SHAPE 路径的带宽陷阱（选中该策略时必查）

- **证据**：已走 SMALL_SHAPE（SIMT 逐元素）路径 + 带宽利用率极低（逐元素读写基线仅约 6.25%）
- **方向**：当 perm 的末轴不参与转置（`perm[permSize-1] == permSize-1`）时，把逐元素读写改为向量化读写——每线程处理 C 个连续元素，恢复 memory coalescing
- **收益**：从 6.25% 带宽利用率基线起步，向量化后提升空间约一个量级
- **排除条件**：末轴参与转置（无连续性可利用，应改走 GATHER 或 VCONV 路径）
- **如何验证见效**：带宽利用率显著上升

## 4.3 N_LAST 路径的写出退化（选中该策略时必查）

- **证据**：已走 N_LAST 策略 + `mte3` 段呈大量小 strided 搬运（写出侧粒度碎）
- **方向**：检查写出循环顺序是否与 output 连续性匹配。当 perm 导致相邻 input 轴在 output 中不连续时，写出会退化为多次 strided 小搬运；可通过检查逆 perm 的连续性，合并 output 中相邻的维度组，把 strided 多循环写出降为连续单次写出
- **收益**：需实测；收益来自写出侧 DMA 粒度增大
- **排除条件**：写出已连续（无退化）
- **如何验证见效**：`mte3` 段搬运次数下降、写出侧带宽利用率上升
